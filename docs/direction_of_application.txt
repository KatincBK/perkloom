==================================================
INTERACTION MODES
==================================================

The distinction between these two modes is one of the most important parts of the app.

-------------------------
1. STATIC MODE
-------------------------

Purpose:
Preserve the user-composed shape of the tree.

Rules:
- nodes should NOT constantly push each other around
- if the user is not dragging and nodes are not overlapping, positions remain exactly where they are
- if I drag a parent node, its whole subtree moves together
- if I drag a child node, that child and its descendants move together
- connection lengths stay as the user arranged them
- the app should not auto-relayout the full tree in static mode
- only local overlap handling should happen when needed

Collision handling in Static Mode:
- if nodes overlap, resolve it locally
- prefer sliding the overlapping node around its parent angularly
- try to preserve the distance to the parent
- avoid changing connection length if possible
- avoid disturbing the overall handmade composition

Interpretation:
Static Mode should feel stable, intentional, handcrafted.

-------------------------
2. RESPONSIVE MODE
-------------------------

Purpose:
Create a lively, self-adjusting, toy-like layout behavior.

Rules:
- nearby nodes repel each other
- parent-child connections behave like soft springs
- edge lengths can stretch or shrink
- dragging one node can cause local reactions in nearby nodes
- after drag stops, nodes softly settle into place
- damping should be high enough that the system never feels chaotic

Important weight rule:
- nodes with larger subtrees should feel heavier and harder to move
- major branch roots should resist disorder more than leaf nodes
- this is important because I do not want large parent structures to get messy too easily

Interpretation:
Responsive Mode should feel alive, elegant, and playful, but still usable and controlled.

==================================================
MOVEMENT PRINCIPLES
==================================================

Please implement motion with smooth transitions, not abrupt jumps.

Use ideas like:
- repulsion between nearby nodes
- spring-like attraction for connected nodes
- damping
- subtree-based mass / inertia
- smooth settling after interaction

This should NOT feel like a chaotic particle simulation.
It should feel designer-friendly and readable.

==================================================
SUBTREE BEHAVIOR
==================================================

Subtree handling is critical.

Rules:
- dragging a parent moves the entire subtree
- dragging a child moves that child and all of its descendants
- in Static Mode, subtree shape should be preserved as much as possible
- in Responsive Mode, subtree internals may react softly, but the structure must remain readable

==================================================
EDGE BEHAVIOR
==================================================

Connection lines must be clean and readable.

Requirements:
- smooth curved lines
- live updates during dragging
- avoid ugly jitter
- visually support the hierarchy

Mode-specific behavior:
- Static Mode: edge lengths are effectively user-defined and stable
- Responsive Mode: edge lengths can be elastic
